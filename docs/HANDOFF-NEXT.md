# Предаване на проекта към новия акаунт

Всичко за продължаването на Siracusa v1 на едно място: какво да направи Поли, преди да започне, кой промпт да даде и кога, и какво трябва да знае новата сесия, за да не повтаря грешките ни.

Състоянието на кода (какво е готово, какво следва) е в `docs/STATUS.md`.

---

## 1. Преди първата сесия (Поли)

1. **Достъп до GitHub.** Новият акаунт трябва да вижда хранилището `vankata54/siracusa-sofia`. Ако е друг GitHub потребител, добави го като Collaborator (Settings → Collaborators). В claude.ai свържи GitHub и инсталирай Claude GitHub App за хранилището.
2. **Нова облачна сесия** на Claude Code с хранилището `vankata54/siracusa-sofia`. Клонът се сменя от промпта; не е нужно да го избираш.
3. **Средата:** стандартната е достатъчна. Трябват npm пакети (позволени по подразбиране); Chromium и Playwright вече са в средата.
4. **Дизайнът като линк.** Артефактът https://claude.ai/artifact/XRaxpFn8UDbBBFDLw6f1YS е на стария акаунт и вероятно няма да се отвори от новия. Не е проблем: целият дизайн е в git (`design/`). Ако искаш линка и там, отвори го от стария акаунт и го сподели.
5. **Пароли:** не са в git. Новата сесия ги създава наново (`scripts/make-env.mjs`) и ще ти ги даде в чата, когато админ панелът е готов.

## 2. Стартов промпт (постави го като първо съобщение)

```

1. git fetch origin build/v1 && git checkout build/v1
2. Прочети внимателно и изцяло, в този ред: CLAUDE.md, docs/HANDOFF-NEXT.md, docs/STATUS.md, docs/BUILD-PLAN.md, docs/AGENTS.md, docs/DECISIONS.md (най-долу печели), docs/OPEN-QUESTIONS.md, docs/CODE-GUIDE.md, docs/PAGE-BRIEF.md, docs/BUILD-TODO.md, design/BRIEF.md (раздели 5 и 8), design/PAGES.md.
3. npm install, node scripts/make-env.mjs, npm test, npm run build. Кажи ми дали всичко минава.
4. Преди да пуснеш агенти, ми върни кратко резюме (до 15 реда) какво разбра: докъде сме, какво следва, правилата. Изчакай „Давай“.
5. После работи по раздел 3 на docs/HANDOFF-NEXT.md, стъпка по стъпка.

Не измисляй факти: каквото липсва, маркирай [ЛИПСВА: ...] и го добави в docs/OPEN-QUESTIONS.md. Говори ми на български, кратко и ясно.
```

Стъпка 4 е нарочна: така виждаш, че новата сесия е разбрала проекта, преди да харчи лимит.

## 4. Правила, които новата сесия трябва да пази (научени по трудния начин)

1. **Шефът комитва, агентите не.** Агентите пипат само своите файлове. Общите (`src/lib`, `src/core`, `src/client`, `src/styles`, `Base.astro`, `server/`) ги променя само шефът или един агент наведнъж.
2. **Всеки агент има свой порт и свои папки за build** (`dist-<страница>*`, в `.gitignore`). Никога `pkill` по общ шаблон: спира чужди сървъри.
3. **Временни файлове** (`*.tmp.config.ts`, `pw-*.config.ts`, `dist-*`) никога в git. Преди комит: `git status` и поглед какво влиза.
4. **Лимити:** партиди по 4-5 агента. При прекъсване се продължава същият агент със SendMessage, не нов.
5. **Проверяващите не поправят**, само описват по `design/REVIEW.md`. Присъдата е ГОТОВО само когато няма блокиращи и важни. Повторна проверка след всяка поправка.
6. **Решенията на шефа се записват** в `docs/DECISIONS.md` с дата (пример: „Натоварено“ е само ръчният превключвател, +20 мин, „около 35 мин“ → „около 55 мин“).
7. **Еднакви думи навсякъде:** „Отивам“ (повикване), „Сервирах“ (готово ястие), „Нова поръчка“, „Изпрати в кухнята“, „Една сметка / По гости / По ястия“, „шофьор“ (не „куриер“), „№ 1042“, „В брой / Карта при получаване / Ваучер“.
8. **Твърдите правила от `CLAUDE.md`:** без измислени факти, маркетингово съгласие винаги неотметнато, без отстъпка срещу Google отзив и Google линкът при Да и при Не, без дълги тирета, текст 16px (14 само етикети), цели ≥ 48px, цветове само от токените, цени `10,22 €`, доставка до 21:00, кухня до 22:30, обедно −30% след 15:00 само за вземане, изчерпаното остава видимо.
9. **Без идентификатори на модели** в комити, код и документи. Пароли само в `.env` и в чата.
10. **Скоростта е приоритет 1:** общият JS на страница е под 30 KB; менюто и иконите не влизат в общия бандъл (`docs/CODE-GUIDE.md`, раздел 3а).

## 5. Кога нещо е „перфектно“ (проверка преди ГОТОВО)

- Изглежда като прототипа на 360, 390 и 1440, в светла и тъмна тема, в часовете, от които зависи.
- Всички състояния: зареждане, празно, грешка, без интернет, затворено, изчерпано, успех.
- Playwright тест за главния поток; без грешки в конзолата; без хоризонтален скрол на 360.
- `npm test`, `npx tsc --noEmit`, `npm run check` (astro check), `npm run build`, `npm run build:demo` минават.
- SEO: един H1, title и description, canonical, JSON-LD по `docs/BUILD-PLAN.md`.
- 2 независими проверяващи с ГОТОВО; запис в `docs/agents-log.md`; комит и push в `build/v1`.
