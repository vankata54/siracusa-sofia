## Как се стартира

```
npm install
node scripts/make-env.mjs   # прави .env със случайни пароли и VAPID ключове (на стар .env добавя само ключовете); не е в git
npm test
npm run build && npm run serve   # http://localhost:8787
npm run build:demo               # статично демо в dist/
```

`npm run test:e2e` сам прави build в `dist-e2e/` (никога в `dist/`), пуска сървъра на порт 8788 с чиста тестова база. Акаунти на персонала: `admin`, `owner`, `manager`, `waiter`, `kitchen`, `driver`; паролите са само в `.env`.

## Уроци

- Агентите работят в отделни git копия (`git worktree add /home/user/rv-<страница>`, `node_modules` като връзка): шефът прилага разликата им (`git diff | git apply`) и комитва. Така проверка и поправки не си пречат с работата на шефа.
- Всеки агент: свой порт и свои папки за build (`dist-<име>*`, в `.gitignore`), никога `pkill` по общ шаблон.
- Шефът комитва; агентите не комитват. В комитите няма идентификатори на модели (и в редовете за авторство).
- Една сесия работи по `build/v1`; паралелни клонове по едни и същи файлове не се сливат.
- Лимитите прекъсват агентите: след нулиране се продължава същият агент (SendMessage), не нов.
- Тест, който зависи от часа на build-а или от натрупани данни, пада „случайно“: e2e тръгват с чиста база, а проверките за текст гледат само съдържанието, което тестват.
