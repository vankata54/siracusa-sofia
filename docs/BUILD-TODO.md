## Първо (стъпка 2 не е завършена)
- Довърши поправките по общите проверки на сайта: `docs/wip/consistency-wip.patch` + `reviews-code/site.fixes.md` (виж docs/STATUS.md).

## Ядро и API
- API за промяна на поръчка „за утре“; Web Push; съгласие за рожден ден без профил; часове на всеки статус в поръчката.
- Офис: кратък адрес за поканата (`/ofis/<код>`) по желание; кодът на поканата е 6 цифри с ограничение на опитите (по-дълъг код иска смяна в страницата и e2e).
- Срязаните адреси на 14 ястия: поле `slug` при генерирането на менюто + 301 от стария адрес (предложението е в `reviews-code/core.agent.md`; чака решение).

## Скорост
- Общият runtime е на ръба (около 29,4 KB при цел 30 000 B): всяка нова обща функция да се зарежда при първа употреба.
- Менюто да се зарежда по-късно на /vzemi-ot-myasto/ (114 KB JS).
- Иконите в един модул (`sc-icons:`) и на страниците, които още ги зареждат поотделно (ястие, оферти, събития).

## Тестове
- E2E: при натоварена машина отделни тестове падат случайно (`home` 48px по време на анимация, `celebration.spec.ts:106` на компютър). Да се стабилизират (изчакване на анимацията/състоянието), без да се пропускат.

## Пускане (етап E)
- Седмичен build (cron): датите на събитията в HTML/JSON-LD са от build-а.
- Зад прокси (Cloudflare, nginx) задължително `TRUST_PROXY=1`, иначе всички клиенти са един адрес за ограниченията.
- SMS доставчик: без него кодът за вход се показва само в демо/тест (`SMS_DEMO=1`); на истинския сайт входът връща грешка.
